The page's edge case 6: after an INSERT into a table with an auto-increment
key, ask for `Statement.RETURN_GENERATED_KEYS` and read the new key from
`getGeneratedKeys()`. And `executeUpdate()` returns how many rows the
statement changed, which is how an UPDATE tells you whether the row existed.

The table is `employees(id INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
name VARCHAR NOT NULL, salary DECIMAL(10,2))`. Write `EmployeeWriter`, given an
open `Connection`:

- `insert(name, salary)` inserts a row and returns **the id read from
  `getGeneratedKeys()`**. **A failed insert throws `SQLException`**: never
  return a made-up id such as -1.
- `updateSalary(id, salary)` returns `true` if a row was changed and **`false`
  when the update count is 0**.

| calls, in order | answer |
|---|---|
| `insert("Ada", 90000.00)` | `1` |
| `insert("Linus", 80000.00)` | `2` |
| (row 1 deleted, rows with ids 100 and 101 written by hand) `insert("Grace", 95000.00)` | `3` |
| `updateSalary(99, 1.00)` | `false` |
| `insert(null, 1.00)` | `SQLException` |
