## How the practices were made

- **Drafting.** Five drafting agents (27, 28, 29 units 1-4, 29 units 5-8, 30) wrote each page's plan (`page.json`: aspects, order, graders, excuses) and its practices from the page and the module's own code, to the pilot's shape: a LeetCode-style statement with an examples table, a starter that throws, a reference, JUnit 5 + AssertJ tests with one method per case, one main case and 1-5 edge cases, each edge with its own plant. Every practice `pom.xml` is the pilot's, with Byte Buddy pinned at 1.17.5. Order is `Page.order`; the quiz is last.
- **Density.** Code-heavy pages (enums, date/time, text blocks, the version pages' new features) carry 4-6 practices; the conceptual ones carry fewer and lean on the quiz: 7.3.2 (the java.time overview) has 2, and 7.1.3 / 7.1.4 have 3 each because text blocks, pattern matching, sealed classes and the Security Manager are either their own modules or not codeable.
- **Pre-gating.** Each draft was proven in the runner before the pass: the reference twice (10 times for the one concurrent practice), the starter once, each plant once (10 times for the concurrent one).
- **The idea rule (arrived mid-run).** Every `practice.json` lists the ideas its statement presents as the point, and every edge names the idea its plant breaks; a check refused any idea no edge breaks. Ideas that cannot be graded by behaviour were un-bolded and moved to a reason or the quiz (examples: 27 `defaults`, "combine both X.super calls"; 27 `seeded`, "check against all()").
- **Adversary rounds.** For every practice a separate agent, which did not write it, wrote subtle wrong solutions (identity/aliasing, default zone/locale/clock, boundaries, rounding, unanchored regexes, shared mutable state) and ran them in the runner. The drafters then closed every real survivor with a test, a new edge whose plant is that mutant, a fixed reference, or a narrowed statement, and the office re-ran every mutant against the final drafts:

## Findings

- **F1: AssertJ `isEqualTo` on a `ZonedDateTime` compares only the instant.** A wrong solution that returns the right moment in the wrong zone, or its input unchanged, passes such a test (29 `meetings`: `forAttendee` returning its argument passed every test). `Optional.contains`, `containsExactly` and `OffsetDateTime` use `equals` and are not affected. S6 compares zoned results by `toString()`. Other offices' zoned tests should be audited; the skill could name this next to the identity rule.
- **F2: the gates prove only the plants an author thinks of.** An independent adversary found 140 real survivors across 101 practices that had all cleared G1-G5, plus four references that broke their own statements (28 `compare-strategy` threw ClassCastException where UnsupportedOperationException was stated; 29 `strict-parse` accepted `+12024-03-15`; 30 `lineCount` and `nest`/`decode` disagreed with their statements). The recurring gaps: default locale/zone/clock (a Turkish or German default, a non-UTC default TimeZone, a winter date), unanchored regexes, boundary inclusivity, rounding vs truncation, shared mutable results, and near-miss types (`Set` for `List`, `Long` for `Integer`). The skill has no step for this; an adversary pass per practice is what closed it here.
- **F3: an edge enforced by the compiler, or an idea with no behaviour, cannot be graded.** G3 needs a plant that passes every main case, so compile-time rules went to the quiz, and ideas such as "combine both `X.super` calls" were un-bolded. The idea rule and G3 together push authors to state only behaviour.
- **F4: a starter that throws the exception an edge expects passes that edge.** 28 `compare-strategy` and `data-converter` expected `UnsupportedOperationException`, which the starter also threw; they now throw `IllegalStateException`. The skill's advice to throw `UnsupportedOperationException` could warn about this.
- **F5: a plant that mutates static state can fail a later main test.** Several 28 practices order such edges after the main case (`@TestMethodOrder`), and locale edges that must see a cached formatter run first (`@Order(1)`); G1 still reruns the reference twice the same way. The skill does not mention test order.

The final ledger holds every row (validate: 0 findings), but the skill does not say whether concurrent passes are safe; a single pass or a lock would be the safe advice.
