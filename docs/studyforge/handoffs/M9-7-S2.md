## How the practices were made

- **The pass.** Each module was one `author_corpus` pass: `material` was the module's `README_*.md` and `graders` its `src/test/**` files. The pass ran with the skill's author, judge and runner. The author read committed drafts.
  - Passes were run one module at a time in the order 07, 08, 09, 10, 06.
  - The ledger's delta on every pass was `dropped: 0` and `changed: 0`. Every other section's rows were kept.
- **Shape.** Each practice is a LeetCode/CodeSignal-style Java task with:
  - a statement with an Examples block;
  - a starter that compiles and throws `UnsupportedOperationException`;
  - JUnit 5 + AssertJ tests, one method per case;
  - one main case (the ask) and 1-4 edge cases, each edge case with its own plausible wrong solution (a plant);
  - the pilot's `pom.xml`: the course's versions, with Byte Buddy pinned at 1.17.5.
- **Commands.** Run is `mvn -o -q -f <workspace>/pom.xml compile`. Submit is `... test`.
- **Order.** Order comes from `Page.order`, with no name prefixes. The quiz comes last.
- **Reuse.** The course's own classes and data are used where they fit. Examples: `Person`/`Person2`, `BankAccount`, `Shape`/`Shape2`, `Calculator`, `Car`/`Vehicle`/`Drivable`, `Employee`, `PersonDTO`, the sealed `Vehicle`/`Car("Tesla")`/`Truck(10000)`, and the pages' Animal/Dog, Point, Printable, PaymentProcessor and `describeShape` examples. No starter hands over the answer, and the worked solution stays behind the framework's closed box.
- **Quizzes.** Each quiz has one or two questions, set with `Page.quiz`. Every Q1, Q2 and Q3 reading was taken by a separate reader agent, never by an author. Q1 and Q3 readers read the page; the Q2 reader read only the stem and options, under `Q2_PROMPT` verbatim, through `page_free`.
  - Readings were taken over each question's digest, and the pass refused any reading whose digest had moved.
  - Before the pass, 8 questions were reworded after a reading refused them:
    - Q2 giveaways: `q-redundant`, `q-interface-helper` (twice), `q-covariant`, `q-tradeoff` and `q-inheritance`.
    - Q3 options no passage refuted: `q-interface-helper` a and c, `q-covariant` b and c, `q-return-type` c, `q-no-arg` c and `q-circular` b.
    - `q-covariant` was replaced by `q-override`, and its aspect now carries a reason. `q-inheritance` was also reworded after a Q1 reader noted that the key made a claim the page does not.
    - Key positions were then shuffled, because the first drafts keyed `a` almost everywhere.
  - Each re-worded or shuffled unit was read again by fresh readers. The shipped readings hold on 36 of 36 questions.
- **Authorship.** Drafting was split across five drafting agents, one per module, directed by this office. Each draft was pre-gated in the same runner before the pass: reference x2, starter, and each plant.
