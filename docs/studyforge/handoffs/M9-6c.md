## How the quizzes were judged

**The readers.** I wrote the questions and judged none of them. Separate agents did, and none saw another's answers:

- **Q1:** two agents, each given the page and the unkeyed questions.
- **Q2:** one agent given only `Q2_PROMPT`, written verbatim to a file it read, plus the stem and the options. Never the page. Its answer is turned into the judgement by `page_free`, never by hand.
- **Q3:** one agent given the page and the keyed questions.

**The rounds.**

- **Round 1** covered all seven questions.
- **Rounds 2 and 3** covered only 1.1.4's `q-decimal`. Each was taken by four new agents after a Q2 refusal. The pass's own retry brief carried the refusal, and the next draft answers the cue it named.

The judge reads the rounds back by each question's digest, so a reading is only ever applied to the exact wording it was taken over.

- `q-switch` (Java 21 Features and Modern Practices:): Per this page, which types can a plain `switch` in Java 21 take as its selector?

  - (b) `char`, `byte`, `short` and `int`, plus their wrappers **(key)**
  - (c) `int`, `long`, `float` and `double`, plus their wrappers

- `q-wrappers` (Common Pitfalls and Best Practices:): Per this page, in which situation is a type such as `Integer` the right choice over `int`?
  - (a) In a performance-critical loop that runs millions of times
  - (b) In a large array that must use as little memory as it can
  - (c) Inside a generic collection, or where null must be allowed **(key)**
  - Q1: `c`, `c`. Q2 page-free pick: `none` (held): "no cue decides it: none of the three situations repeats a word from the stem, none is markedly longer or more specific than the others, and no option carries an absolute term the others lack". Q3: a ruled out, b ruled out.

**1.1.2: Where values live, and when they are collected**

- `q-storage` (Interview Questions:): Where does this page say the value of an `int` field of an object lives?
  - (a) On the stack of the thread that created the object
  - (b) In a separate heap object that the field points to
  - (c) Inside the object itself, which sits on the heap **(key)**
  - Q1: `c`, `c`. Q2 page-free pick: `b` (held): "(b) repeats two of the stem's own words, 'field' and 'object', while (a) and (c) each repeat only 'object'". Q3: a ruled out, b ruled out.
- `q-gc` (Interview Questions:): Why does this page say its `GarbageCollectionDemo` prints different output on different runs?
  - (a) `System.gc()` is only a request, and the JVM may exit before finalizers run **(key)**
  - (b) `finalize()` runs on a thread the scheduler picks afresh for every object
  - (c) `obj2` stays reachable until `main` returns, so it is collected much later
  - Q1: `a`, `a`. Q2 page-free pick: `none` (held): "no cue decides it: each option names its own specific token (System.gc(), finalize(), obj2/main) but none repeats the stem's own wording ('GarbageCollectionDemo', 'prints', 'different', 'output', 'runs'), and there is no absolute term or length difference singling one out". Q3: b ruled out, c ruled out.

**1.1.3: The cost of boxing in a loop**

- `q-boxing` (Interview Insights:): What does this page say is wrong with `Integer sum = 0; for (int i = 0; i < 1000000; i++) { sum += i; }`?
  - (a) Nothing costly: the compiler keeps `sum` as a plain `int` in the loop
  - (b) Every pass boxes `i` into an `Integer` before comparing it to the limit
  - (c) Every `+=` unboxes the total and boxes a fresh `Integer` for the result **(key)**
  - Q1: `c`, `c`. Q2 page-free pick: `none` (held): "no cue decides it: each option matches exactly two tokens from the stem's code (sum/int in (a), i/Integer in (b), +=/Integer in (c)); (a) alone denies the stem's premise that something is wrong, but that still leaves (b) and (c) tied with nothing to choose between them". Q3: a ruled out, b ruled out.
