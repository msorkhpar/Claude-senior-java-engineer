## Pack

- **Tag: reuse `narration-1.0.0`.** The skill's rule is that a tag is published once, because `gh release create` fails when that tag's release already exists. But `narration-1.0.0` was never uploaded. The earlier pack's files (`11afe34f`) are on no remote either: `origin/main` has no `.studyforge/narration-release/`. So no release and no clone holds the old digests. A new pack rewrites `SHA256SUMS`, `clips.sha256` and the scripts under the same tag, and nothing can disagree with them. A new tag is only needed once `narration-1.0.0` has been published.
- **Volumes:** none were written. At 1,980,441,284 bytes of clips, the pack will be three volumes: two of 999,000,000 bytes and one of about 0.98 GB, plus `SHA256SUMS`.
- **Upload command:** none was printed, because `--publish` needs the volumes. Once the pack is GREEN, the dry run prints a command of this shape. **Do NOT run it; the upload is the user's.**
  `gh release create narration-1.0.0 <scratch>/volumes/narration.zip.000 … <scratch>/volumes/SHA256SUMS --repo <owner>/Claude-senior-java-engineer --title Narration --notes '…'`
- **To finish, from this worktree once there is room for about 2 GB:**
  1. Run `studyforge narrate . --pack <dir> --tag narration-1.0.0`.
  2. Commit what it writes: `.studyforge/narration-release/` (the restore scripts, `SHA256SUMS` and `clips.sha256`).
  3. Run `studyforge narrate . --publish <dir> --tag narration-1.0.0`, and hand over the printed command with the owner as `<owner>`.
