## The quizzes, and why none shipped

**What Q2 checks.** Q2, "not free", holds when an independent pass is given the question **without the page** and does **not** pick the key. It proves that the question tests what this page taught rather than general knowledge. Q1 (two readings with the page, both must pick the key) and Q3 (a page passage rules out each wrong option) are the other two judged gates.

**How it was judged.** I wrote the questions, and never judged them. Four separate agents took the readings:

- two Q1 readers, each given the page and the unkeyed questions;
- one Q2 reader, given the questions only, and told it could answer "none";
- one Q3 reader, given the page and the keyed questions.

The pass's `judge` reads those four JSON files back, and each `Judgement` carries its prompt, who took it, and what it said. A first round had every key at option (a), so I reordered the options and every reading was taken again on the new wording.

**The seven questions and their readings:**

**1.1.1 — What the compiler and the JVM decide about primitives**

- `q-switch` (Java 21 Features and Modern Practices:): What does this page say a plain `switch` on primitives accepts in Java 21, and when may a primitive type appear in a pattern?
  - (a) Any primitive type, because Java 21 finalised pattern matching for `switch`.
  - (b) Only `char`, `byte`, `short` and `int` (and their wrappers); primitive patterns arrive only as a preview feature in Java 23. **(key)**
  - (c) `long` and `double` as well, because `var` infers their type.
  - Q1 picks: `b`, `b` (held). **Q2 pick without the page: `b` (refused)**, because: "Plain switch on primitives has always covered char/byte/short/int (and wrappers), while primitive type patterns are only a preview feature (JEP 455) introduced after Java 21, in Java 23.". Q3: a: held c: held.
- `q-wrappers` (Common Pitfalls and Best Practices:): According to this page, when should you use a wrapper class such as `Integer` instead of `int`?
  - (a) In performance-critical loops, because wrapper objects are cached.
  - (b) For large arrays, because wrapper arrays use less memory.
  - (c) When working with generic collections, or when null is a valid value. **(key)**
  - Q1 picks: `c`, `c` (held). **Q2 pick without the page: `c` (refused)**, because: "Wrapper classes are needed for generic collections (which can't hold primitives) and whenever a null value must be representable.". Q3: a: held b: held.

**1.1.2 — Where values live, and when they are collected**

- `q-storage` (Interview Questions:): Where does this page say the value of an `int` field of an object lives?
  - (a) On the thread's stack, because it is a primitive.
  - (b) In a separate object on the heap that the field refers to.
  - (c) Inside its object, on the heap. **(key)**
  - Q1 picks: `c`, `c` (held). **Q2 pick without the page: `c` (refused)**, because: "A primitive int field is stored directly inside the object's memory layout on the heap, not boxed separately and not on the stack.". Q3: a: held b: held.
- `q-gc` (Interview Questions:): The page's `GarbageCollectionDemo` calls `System.gc()` and overrides `finalize()`. What does the page say you see when you run it a few times?
  - (a) Both messages every time, because `System.gc()` forces a collection.
  - (b) Sometimes both messages appear, and often neither does. **(key)**
  - (c) A compile error, because `finalize()` was removed in Java 18.
  - Q1 picks: `b`, `b` (held). **Q2 pick without the page: `b` (refused)**, because: "System.gc() is only a hint to the JVM and finalize() timing is unpredictable, so running it repeatedly yields inconsistent results rather than a guaranteed or a compile-time outcome.". Q3: a: held c: held.

**1.1.3 — The cost of boxing in a loop**

- `q-boxing` (Interview Insights:): The page's loop `Integer sum = 0; for (int i = 0; i < 1000000; i++) { sum += i; }` is flagged as a problem. What does the page say it does, and what does it do instead?
  - (a) Nothing extra, because every `Integer` is cached; no change is needed.
  - (b) It creates 1,000,000 `Integer` objects; keep the sum in an `int` and box once at the end if needed. **(key)**
  - (c) It boxes each value; calling `Integer.valueOf(i)` explicitly inside the loop avoids that.
  - Q1 picks: `b`, `b` (held). **Q2 pick without the page: `b` (refused)**, because: "Using an Integer accumulator in a tight loop causes repeated autoboxing, creating up to a million Integer objects; the fix is to accumulate in a primitive int and box only once at the end.". Q3: a: held c: held.

**1.1.4 — How an expression is read**

- `q-precedence` (Key Points to Remember): How does this page say Java reads the expression `!a == b`?
  - (a) As `!(a == b)`, because relational operators bind tighter than logical ones.
  - (b) It does not compile without parentheses.
  - (c) As `(!a) == b`, because the unary `!` binds tighter than `==`. **(key)**
  - Q1 picks: `c`, `c` (held). **Q2 pick without the page: `c` (refused)**, because: "In Java the unary logical NOT (!) has higher precedence than the equality operator (==), so !a == b is parsed as (!a) == b.". Q3: a: held b: held.
- `q-decimal` (Best Practices and Optimization Techniques): Which type does this page suggest for precise decimal calculations, such as financial ones?
  - (a) `BigDecimal`. **(key)**
  - (b) `double`, compared with a tolerance.
  - (c) `float`, because it is faster than `double`.
  - Q1 picks: `a`, `a` (held). **Q2 pick without the page: `a` (refused)**, because: "BigDecimal is the standard recommendation for exact decimal arithmetic such as money, since double/float suffer from binary floating-point rounding error.". Q3: b: held c: held.

## Question for the owner

**Q5. Quizzes on well-known technical material cannot pass Q2 with a model as the page-free judge.**

| option | what it means |
|---|---|
| **a.** Ship no quizzes on such pages | Keep what is committed. The quiz-suited concepts stay "planned, refused by Q2" in each `coverage.json`. |
| **b.** Re-define the page-free judge (studyforge row) | Q2's reader is someone who has **not studied the topic**, not a knowledgeable model. This could be a judge told to answer only from the question text and to say "none" when the question needs domain knowledge, or a Q2 that holds when the page is needed to rule out a distractor. This changes what the gate proves, so it is an owner decision. |
| **c.** Let a corpus declare that its subject is general knowledge (studyforge row) | Q2 is waived for that corpus, and the quiz records say so. |
| **d.** Rewrite the questions toward page-specific detail | The skill discourages this, and it is fragile against a strong judge. |

**Recommendation: b.** Q1 and Q3 already prove each question is answerable from the page and fair. What a technical course needs Q2 to guard against is a question the page does not teach, not one an expert already knows. Until then, **a** is what is committed.
