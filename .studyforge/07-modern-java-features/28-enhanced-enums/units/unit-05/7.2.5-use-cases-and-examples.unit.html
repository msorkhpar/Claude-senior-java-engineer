  15. Check yourself: enum use cases

A customer cancelled an order and got a refund. An hour later the warehouse's "shipped" event arrived, the handler wrote its status into the order, and the parcel went out anyway. The status field was an enum, and an enum field accepts any constant, in any order. An enum can enforce which states may follow which, but only if you put the table somewhere.

Here are four jobs enums do in production code: the singleton, flag sets, state machines and configuration keyed by a constant. What an enum can't do is unit Limitations of Traditional Enums. Enums can't be generic (JEP 301 proposed it and was withdrawn; unit Declaring Generic Enums), constructor arguments and constant-specific bodies are unit Parameterized Enum Constants, and generic methods on an enum are unit Generic Methods in Enums.

An Enum With One Constant Is a Singleton That Reflection and Serialization Can't Copy

The usual singleton is a class with a private constructor and one static instance. This one hands out order ids:

Before reading the output, predict how many instances of each exist after a serialization round trip and after a reflective call to the private constructor. The program writes each INSTANCE to an ObjectOutputStream and reads it back, then calls getDeclaredConstructors()[0], setAccessible(true) and newInstance(...):

The private constructor stops other code from writing new IdSequence(), nothing more. Deserialization builds a new object without calling it, and setAccessible opens it. The reflected copy's counter starts at zero and the deserialized one resumes from the value written, so two parts of the service hand out the same ids and the second insert fails on a duplicate key. A readResolve method returning INSTANCE fixes the round trip; it does nothing against the reflective call.

The enum needs neither. Constructor.newInstance refuses any enum class, and an enum is serialized as its name and read back with valueOf, so the reader gets the constant that already exists in its own JVM. Its fields don't travel. Here one JVM takes 41 ids and writes INSTANCE to a file, and a second JVM reads it:

If the state matters elsewhere, store it yourself. Every thread shares the constant's fields, which is why the counter is an AtomicLong. And code that names Ids.INSTANCE can't be handed another implementation in a test: let the enum implement an interface and pass the interface around.

EnumSet Is a Typed Bit Mask, and a Shared One Must Be Unmodifiable

Permissions as int flags look cheap, but nothing ties a flag to its family:

A user's notification settings passed as permissions compile, run and give read-write access, and the log shows 3. With enum Permission { READ, WRITE, DELETE } and an EnumSet, the same mistake doesn't compile, and the set prints its names:

The type costs nothing at run time. The EnumSet javadoc describes a bit vector with constant-time basic operations, a typesafe alternative to int-based bit flags. In the JDK's source, a set of an enum with up to 64 constants is a RegularEnumSet, which keeps one long. When the set must be stored, store the names (READ,WRITE), not the ordinals or a mask built from them: inserting a constant shifts every later bit, as unit Limitations of Traditional Enums shows for ordinals.

EnumSet is mutable, and final fixes only the reference. The Permission enum in this module's example code declares public static final Set<Permission> READ_ONLY = EnumSet.of(READ), and one caller starts a guest from it:

The EnumSet.of call ran once, when the class was initialized; every user of the field holds that one set. Every role built on READ_ONLY can now write, until the JVM restarts. Wrap shared sets with Collections.unmodifiableSet, so the add throws UnsupportedOperationException, and build a user's set as a copy: EnumSet.copyOf(READ_ONLY). copyOf(Collection) takes the enum type from the first element, so an empty collection that isn't itself an EnumSet throws IllegalArgumentException: Collection is empty. Start from EnumSet.noneOf(Permission.class) and addAll instead when the source can be empty.

Enum-Keyed Configuration Belongs in an EnumMap Checked for Every Key at Startup

A notification service reads a rate limit per channel from a properties file (limit.EMAIL=500, limit.SMS=20) into an EnumMap<Channel, Integer>. A release adds Channel.PUSH, and nobody adds limit.PUSH to the file. The service starts cleanly. Hours later the first push notification fails:

A map answers a missing key with null, so the error waits for the first caller. Since the enum lists every key the map must hold, the loader can check them all before it returns:

The deploy fails, with the channel's name, before any traffic. The shorter EnumSet.complementOf(EnumSet.copyOf(m.keySet())) gives [PUSH] here too, but an EnumMap's key set is not an EnumSet, so on an empty file it throws Collection is empty instead of naming every channel. A key that names no constant, such as limit.EMIAL, makes Channel.valueOf throw IllegalArgumentException; catch it and report the key.

When the values are constants in code rather than a file, a switch expression with no default gives the same guarantee at compile time: adding PUSH breaks the build when the switch is recompiled (unit switch expressions (Java 14+)).

Summary

  • An enum singleton can't be copied. Constructor.newInstance refuses enums and deserialization returns the existing constant; its fields don't travel, and every thread shares them.
  • `EnumSet` is a bit mask with a type. A set from another enum doesn't compile, it prints names, and a shared one must be unmodifiable or one caller's add changes everyone's. Store names, not ordinals.
  • A state machine keeps its transitions in an `EnumMap` filled in a static initializer. A constant can't name a later one in its arguments, and a state without a row gives null.
  • Enum-keyed configuration is an `EnumMap` checked against `EnumSet.allOf` at load, so a new constant without a value stops the deploy rather than the first request.

Challenges

  1. Your permission sets are stored as an int mask column in 40 million rows. Plan the move to names: what runs during the migration, and what does a reader of half-migrated data see?
  2. The order lifecycle gains RETURNED and REFUNDED. Where would you write the test that proves every state has a row and every terminal state is intended?
  3. A Spring bean and an enum singleton both give one instance per JVM. For an id generator that must be faked in tests, which do you choose, and what does the other cost?

Design Note: An Enum Fixes Its Instances When the Class Is Compiled

Every use case on this page rests on one property: the set of instances is closed and known to javac. That is what lets newInstance refuse to build one more, lets EnumSet give each constant one bit, and lets an EnumMap be an array. The cost is that the set can only change with a release. Permissions that an administrator defines at run time, or workflow states that a customer configures, don't fit an enum; they belong in data, with the checks this page gets from the compiler written by hand.
