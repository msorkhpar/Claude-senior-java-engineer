An Instance Method Is Chosen by the Object; a Static Method by the Declared Type

Both exporters declare a static extension() and an instance format():

Predict the four lines:

Compiled with -g, which names the variable in the message:

An instance call's implementation is chosen when it runs: the JVM looks at the object's class and runs its override, so format() says csv. A static call is resolved by the compiler, from the type of the expression left of the dot. That expression is still evaluated, but its value is thrown away, which is why the call through null works. javap -c shows the two instructions:

CsvExporter.extension() hides Exporter.extension(): it runs only when the call names CsvExporter or an expression of that type. The compiler can tell you: @Override on a static method fails with static methods cannot be annotated with @Override, and javac -Xlint:static warns about every static call made through an expression.

The export service built names as base + "." + exporter.extension() with exporter typed as Exporter, so every format got .dat. The call through null is a latent bug: it works until someone turns the method into an instance method, and then a null that was always there throws.

Every Argument Is Evaluated, Left to Right, Before the Method Runs


As with operands (unit Arithmetic, relational, and logical operators), Java evaluates the expression before the dot, then each argument in order, and only then checks the receiver for null and enters the method. Debug is off and debug checks the level itself, audit() returns null because auditing is off, and render and nextSeq print when they run:



The program prints a header before each call, catches the exception, then takes the next number:



debug(String) never used its argument, but the order was rendered before debug started. A logging placeholder ("placing {}", render(order)) defers only the formatting: render still runs. A Supplier lets the method decide whether the work happens. The same holds for any "default" argument, such as Optional.orElse(...) or Map.getOrDefault(key, ...): it is computed whether or not it is needed.


The null receiver threw only after both arguments ran, so sequence number 42 went to a record that was never written. Check a receiver that can be null before computing arguments with side effects.

Each Call Holds a Stack Frame Until It Returns, So Recursion Depth Is Limited by the Stack


A call's frame, with its parameters and locals, stays on the stack until the method returns, so recursion keeps the whole chain's frames alive. The support page renders replies recursively, and the failing thread is a chain of 12,000 replies, each answering the one before:



We render it right after the JVM starts, then again after rendering 20,000 short discussions has warmed render up, on the default 1 MB stack:



Two more runs failed after 10,203 and 10,972 lines. The limit is bytes of stack. A frame of the interpreted method is larger than the frame of the same method once the JIT has compiled it, and when that happens varies from run to run. So the thread fails after each deploy and loads once the server is warm.


-Xss2m made the first attempt succeed too, but it only moves the limit, for every thread that doesn't set its own. HotSpot doesn't eliminate tail calls either: return count(n - 1, acc + 1); still overflowed at 1,000,000. For data whose depth users control, keep the pending work on the heap:




The children are pushed last first, so they come off in the recursion's order. This version leaves out the depth, which the stack would have to carry too.

Summary


  • An instance method is chosen by the object's class at run time; a static method by the declared type at compile time. A subclass's static method hides the parent's, and a static call through null runs.
  • A private method is never overridden. The class's own calls keep using it; @Override turns the mistake into a compile error.
  • Every argument is evaluated, left to right, before the method runs, even when the method ignores it and even when the receiver turns out to be null.
  • Recursion depth is limited by stack bytes, which change as the JIT compiles. Recursion over data whose depth users control needs an explicit stack.

Design Note: Why a Static Call Is Bound at Compile Time


A static method has no receiver, so when it runs there is no object whose class could pick an override. Java resolves the call against the type the compiler sees, which is cheap, and leaves per-type behaviour to objects. The cost comes when a static utility, such as a clock, later needs to vary. It must become an instance method on an object that callers receive, and every caller changes. That is why code meant to be tested takes a java.time.Clock instead of calling System.currentTimeMillis().
