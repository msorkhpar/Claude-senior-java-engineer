A logistics service moves from Java 8 to 21. The first shipment it saves throws InaccessibleObjectException from the audit logger, which writes every saved object field by field. The test suite fails too: a helper that swaps the billing code's static final Clock for a fixed one, by clearing the field's FINAL bit first, now gets NoSuchFieldException. Nobody changed either helper.

Once you hold a Field, Method or Constructor (unit Class and Object Introspection finds them), setAccessible(true) switches off the language's access check for get, set, invoke and newInstance. The sections below are the places where it stops working. Every output is from Java 21; Java 25 printed the same for the four programs.

setAccessible Opens Your Own Classes, and java.base Only One Granted Package at a Time

The audit logger, reduced to its walk:

Pause before the output: which field stops the walk, and what does one --add-opens change?

Code on the class path sits in the unnamed module, and setAccessible succeeds on any of its members. A class in a named module opens its private members only if its module opens the package to the caller. java.base opens none of its packages (unit Public, private, protected, and default access modifiers shows it on String.value, unit Java 17 (LTS) on the Java 17 upgrade), so the walk fails at the first JDK object it reaches. Each grant covers one package: opening java.util moved the failure to java.time. An executable jar can carry the same grants in its manifest, Add-Opens: java.base/java.util java.base/java.time. java -jar dump.jar printed the third line; the same jar run with -cp failed at java.util, because the attribute is read only with -jar.

That third line is also why the grant is a poor fix. The dump now shows elementData and seconds, the JDK's private layout, which any release may change, and the parcel IDs are missing: an array has no declared fields, so the walk never prints the elements.

InaccessibleObjectException extends RuntimeException, so dump's throws IllegalAccessException and a caller's catch (ReflectiveOperationException e) both miss it, and the save fails. A walker that must survive classes it can't open asks first. trySetAccessible() returns false where setAccessible would throw, and in place of the setAccessible line the walker returns the object's public toString():

  1. Coding practice

    Let the debug endpoint write objects it can't open

    • setAccessible succeeds on class-path code but throws InaccessibleObjectException, an unchecked exception, on a private member of a JDK class; trySetAccessible returns false instead, so a walker can fall back to the object's public API.

A Final Instance Field Can Be Written, and Code Compiled Against Its Constant Never Sees It


A retry policy has one final field initialised with a constant and one assigned in the constructor:





Both writes succeeded. The getter still returns 3 because it never reads the field. A final field initialised with a constant expression is a constant variable, and javac compiles its value into the code that reads it. javap -c shows it:



The constructor-assigned field changed for every reader here, but nothing promises that. The Field.set javadoc calls writing a final field meaningful only for blank finals (backoffMs, not maxAttempts) during deserialization or reconstruction, before other code can see the object. Anywhere else, it warns, other parts of the program may go on using the original value. A reflective write to a final field belongs in code that builds the object, not in code that changes one already in use.


A Static Final Field and a Record Component Refuse the Write


The billing test from the opening swaps a static final Clock; a second test edits a record:





setAccessible(true) succeeded on both fields, and set refused anyway. The Field.set javadoc grants write access to a final field only when it is non-static and its class is neither a record nor a hidden class. Unit Singleton Pattern (ensuring a single instance) met the same refusal resetting a singleton's INSTANCE.


That refusal is older than modules, which is why the opening's helper first cleared the FINAL bit through the private modifiers field of Field itself. On Java 21 reflection doesn't list that field, so the trick ends in NoSuchFieldException. A test that needs a fixed clock passes it in, through a constructor or a parameter, and the production code reads the injected Clock.


Reflection can't change a record's fields either, so a deserializer or a copy helper builds a record through its canonical constructor. That constructor runs the record's validation, which a field write would skip.

Method.invoke Wraps the Method's Exceptions and Throws Its Own Argument Errors Unwrapped


An admin endpoint calls handler methods by name. It answers 400 to bad input and 500 to anything else. refund rejects a non-positive amount with IllegalArgumentException:



The endpoint finds the public method by name and calls it:



Two requests: an amount of -500, and an amount sent as the string "500". Which status does each get?



Both answers are wrong. invoke never lets the method's exception through: it wraps whatever the method throws, checked or unchecked, in InvocationTargetException, a checked ReflectiveOperationException, with the original as getCause(). So the refund that refund rejected became a 500 with no message. The string never reached refund: invoke threw that IllegalArgumentException itself, because the argument didn't fit the int parameter, and it doesn't wrap its own exceptions. The first case reports a client's mistake as a server error, and every 500 pages the on-call engineer. The second blames the input in words that name no parameter.

Summary


  • setAccessible opens class-path code; a java.base package opens only by --add-opens or Add-Opens, one package at a time. InaccessibleObjectException is unchecked, and trySetAccessible() lets a walker fall back to the public API instead.
  • A final instance field can be written, and code compiled against its constant never sees it. javac inlines constant values, and the javadoc warns that other readers may keep the old value.
  • A static final field and a record component refuse the write after setAccessible. The modifiers trick is gone; inject the value, or call the canonical constructor.
  • Method.invoke wraps what the method throws in InvocationTargetException and throws its own IllegalArgumentException unwrapped. Decide by the wrapper, then read getCause().

Design Note: Why the JDK Closed Its Packages


Until Java 9, setAccessible(true) reached everything, and serialization and mocking libraries came to depend on the JDK's private fields. Each such dependency froze a piece of the JDK's internals, because changing a private field broke code that was never meant to see it. Modules let java.base say which packages are API, and strong encapsulation, the default since Java 16 and the only mode since 17, makes every exception visible at launch: an --add-opens or an Add-Opens entry names the package and the module that gets it.


The cost falls on generic tools. A serializer or a deep-copy helper now needs either a grant per package or a fallback to the public API, which loses whatever that API doesn't show. The final rules make the same trade: a static final field or a record component that core reflection can't change is one the rest of the program can rely on.
