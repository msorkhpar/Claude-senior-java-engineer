An Element Holds a Compile-Time Constant of a Few Types

An annotation type is declared with @interface. Which of these elements compile?

None compiles. An element's type is a primitive, String, Class, an enum, another annotation, or a one-dimensional array of one of these. Every value, the defaults included, is fixed when javac runs: the class file stores it as a constant, an enum constant's name, a class name, a nested annotation or an array of these, so the JVM can rebuild it without calling the code that computed it. A List, an Integer or a call has no such form. null has none either, so "not set" needs a sentinel: "", -1, or Void.class for a Class element.

The value must be a constant expression in the language's sense, and a static final field is not always one:

A team that wants the retry count to come from configuration can't put it in the annotation, as a default or at the use site. The annotation names a key (@Retry(attemptsKey = "orders.retries")), and the code that reads the annotation looks the value up.

@Target Is Checked by javac at Every Use

A timing aspect wraps methods annotated @Timed, and someone writes @Timed on a field. With @Target(ElementType.METHOD), javac refuses it:

Without @Target, the field compiles, the aspect never looks at fields, and nothing is timed. An annotation type with no @Target is accepted on every declaration, a type parameter included, and in no type context:

Annotations written on a type, such as List<@NonNull String>, need ElementType.TYPE_USE in the target.

A Repeated Annotation Is Stored Inside Its Container

The opening's service and its guard:

@Repeatable(Roles.class) lets you write @Role more than once. When you do, javac writes a single @Roles({@Role("ADMIN"), @Role("AUDITOR")}) into the class file instead (javap -v shows only Roles on voidPayment), and no @Role is directly on the method. getAnnotation(Role.class) returns null, and the guard opened the method to anyone. A single @Role is stored as itself, so getAnnotation(Roles.class) is null there. Code that reads only the container breaks on the other half of the methods.

getAnnotationsByType(Role.class) looks through the container and returns every @Role in the order written, for one or for many, so code that reads a repeatable annotation should use it.

javac checks the container against the repeatable annotation, among other rules: it needs a value() element of the repeatable type's array, a retention at least as long, and targets that are a subset of the repeatable type's. Forget its @Retention, and it defaults to CLASS:

@Inherited Reaches a Class Only from Its Superclasses

An audit interceptor logs every call to a class carrying @Audited and reads the level from it:

StripeService declares nothing and still gets BASIC. When a class has no @Audited of its own, getAnnotation asks its superclass, then that one's superclass, and returns the first it finds, so the nearest declaration wins and FULL two levels up is never seen. getDeclaredAnnotation skips that search. @Owner has no @Inherited, so it stays on BaseService.

LedgerService implements an audited interface and isn't audited: the @Inherited javadoc says annotations on implemented interfaces have no effect. StripeService.pay() overrides an audited method and isn't audited either: @Inherited has no effect on anything but a class, even though Audited allows METHOD. A developer who overrides pay() to add a log line has removed its auditing.

A superclass chain has one nearest declaration; a class can implement two interfaces that carry different values. A library that wants interface or method annotations walks the hierarchy in its own code, with its own rule for which declaration wins.

Summary

  • An element holds a compile-time constant of a primitive, String, Class, enum, annotation or a one-dimensional array of these. No null, no collections, nothing computed at run time: configuration can't reach an annotation.
  • Defaults live in the annotation type and are filled in when the annotation is read, so a library that changes a default changes every caller that didn't set it. Only value may be written unnamed, and only when every other element has a default.
  • `@Target` is checked by javac at every use. Without it, a misplaced annotation compiles and is silently ignored by whatever reads it.
  • A repeated annotation is stored inside its container. getAnnotation(Role.class) misses a repeated @Role, and a guard that reads it opens the method; getAnnotationsByType finds every one.
  • `@Inherited` reaches a class only from its superclasses, nearest first. Interfaces, methods and fields inherit nothing.

Challenges

  1. A security library must decide whether a method with no @Role is open or closed. Which default would have made the opening's bug fail safe, and what would it cost a team adopting the library on an existing code base?
  2. You need @Endpoint timeouts to differ between staging and production. Design the annotation and its reader so that no value is compiled into a class file.
  3. Write a lookup that finds @Audited on an interface method when the implementing method has none. Decide what it does when two interfaces disagree, and when a superclass method disagrees with an interface.

Design Note: Annotations Are Constants So the JVM Can Read Them Without Running Code

The element rules on this page follow from one choice: an annotation's values live in the class file as constants. Reflection rebuilds an annotation from those bytes, a processor reads them before the program exists, and a tool can read them from the class files without loading a class.

The cost is that an annotation can't express anything that is decided later: an environment's timeout, a role list from a database, null. Those end up as keys and sentinels that some other code resolves, and the annotation then states only part of what happens. The default is the exception: it is looked up in the annotation type when the annotation is read, which is why an upgrade can change it without a rebuild.

Problem statement


The tracing agent decides per handler class how closely to trace it, from a @Traced(level = ...) annotation. Teams put it where it suits them: on the handler class, on a base class their handlers extend, or on a service interface such as Ingest, which a handler may implement directly, through its base class, or through another interface (interface BulkIngest extends Ingest). After the last release the agent's dashboards show no traces from about a third of the handlers, all of them handlers that teams say are annotated.


Finish levelOf(Class<?> handler) and fromInterfaces(Class<?>[] interfaces) in src/main/java/practice/TraceLookup.java. A handler is traced at the level of the @Traced on its class or nearest superclass; failing that, at the level of the first traced interface found from the class upward; with none anywhere, it isn't traced. About twelve lines in total.
