A Constructor That Fails Has Already Published this If It Registered Itself First

A meter adds itself to the scheduler's list, then checks its interval:

After new Meter("m-1", 60), new Meter("m-2", 0) is refused, and the scheduler then polls what it holds:

The object exists before the constructor body runs. The exception stops new from returning a reference, but one already handed out survives, with its fields at their defaults: null every 0 s. The crash comes on every later poll, far from the line that refused the meter. Registering a listener, starting a thread or caching this does the same. Check every argument first, assign, and publish last, or let a factory publish the finished object.

An Immutable Class Is final, and Copies Every Mutable Part, Not Just the Collection

Money has private final long cents, a getter and no setters, so Invoice keeps the Money it is given without copying it; dueCents() returns total.cents(). But Money isn't final:

BigDecimal and BigInteger can be subclassed too, so code that keeps one from a caller it doesn't trust checks its exact class or copies it. Make the class final, or give it only private constructors and static factories.

A final field holds a reference, so immutability goes only as deep as the copy. List.copyOf copies the list, not its elements (unit Pass by value and pass by reference). Holidays keeps a list of java.util.Date:

Hold immutable elements (LocalDate, Instant, String), or copy each one in and out. A class whose fields are all final also gets the publication guarantee of unit Synchronization actions and their impact on memory visibility, provided its constructor doesn't publish this.

Deserialization Builds the Object Without Your Constructor, So readObject Checks Again

Stay refuses fewer than one night in its constructor. A record StayRecord(int nights) has the same check in its compact constructor, and CheckedStay, the class again, repeats it in readObject:

We serialize each with three nights, set the four bytes of nights in the stream to zero, and read it back. Both classes print themselves in the record's format:

For a Serializable class, ObjectInputStream runs only the no-arg constructor of the first superclass that isn't serializable, here Object's, then sets the fields from the stream. A record is rebuilt through its canonical constructor. The stream needn't be forged: objects written before the check existed carry such values too. Throw InvalidObjectException, an IOException, so a caller that handles a bad stream handles this one.

A serializable singleton comes back as a second instance, unless a readResolve() method returns the existing one.

Summary

  • Check every argument before the constructor publishes `this`. A reference handed out before the throw survives it.
  • An immutable class is `final` and copies every mutable part. A subclass or a shared element changes what callers were told can't change.
  • Deserialization skips your constructor, records excepted. readObject repeats the checks and throws InvalidObjectException.
  • Reflection can rewrite a `private final` field of an ordinary class, not of a record. A test that does it breaks when the class becomes a record.

Challenges

  1. A class you own has been serialized into a cache for two years. You add an invariant. What happens to the entries already there, and how do you find out before the release?
  2. A method of yours keeps a BigDecimal from its caller. Copy it, check its class, or accept the risk? What does each cost?
  3. A test sets a private final field by reflection. Which change to the class breaks that test?

Design Note: Why Serialization Skips the Constructor

Serialization restores an object's fields, private ones included, so it works for classes with no constructor that takes those fields. The cost is a second way to create objects, one the class's author doesn't see. Records changed that: their state is their components, so the stream is read back through the canonical constructor.

The authorizer builds one AccessPolicy at startup from a table the config loader produces, and asks it on every request. Last week an auditor exported customer data the policy had never granted. The loader reuses its lists when it reloads, and a plugin ships a class that extends AccessPolicy.
